# 2026-09-24 R5 补充：中文版报告（对照译本）

> 关联：`report/report_zh.html`（源）、`report/report_zh.pdf`（12 页产物）、
> `report/build.sh`（新增 `zh` 分支）；对照 `report/report.tex` / `report.pdf`（英文提交版）
> 重建命令：`cd report && bash build.sh zh`

## 问题定义

英文版报告（`report/report.pdf`）是提交物，但作者本人（以及后续答辩准备）需要一份中文
对照版本以确保每一节、每一个数字、每一张表图都被真正读懂，而不是"自己写的、
自己知道对"。因此本条记录的目标是：产出一份与英文版**逐节、逐表、逐图、逐数字**对齐的
中文版，放在 `report/` 下。不改变任何实验结果，不新增任何数字——中文版只是英文版的
另一种语言载体。

用户明确说明"不一定用 LaTeX，HTML 也行"。

## 方法

- **路线选择：HTML + Chrome headless 打印 PDF**（而非 LaTeX 的 ctex/xelatex）。
  理由：本次报告有大量表格与需要一一对应的图，HTML 的表格与排版迭代快、diff 友好；
  环境里 Chrome 151 已就绪，零安装成本；LaTeX 中文路线需要 ctex 字体包
  （Fandol/Noto），在无 sudo 的 WSL 里装起来比重编整套宏包更折腾。
  代价：LaTeX 版有严格的 `break-inside: avoid` 等分页控制，HTML 版靠 CSS 的
  `break-inside: avoid` + `break-after: avoid` 近似，个别页可能不如 LaTeX 紧凑。
- **字体**：从 WSL 可读的 Windows 字体目录复制到 `~/.local/share/fonts/`：
  `msyh.ttc`（雅黑，备用）、`simsun.ttc`（宋体，正文）、`simhei.ttf`（黑体，标题），
  `fc-cache -f`。CSS 里正文 `"SimSun", serif`，标题 `"SimHei", sans-serif`。
  原先 WSL 只有文泉驿正黑/AR PL 系列，排版效果偏港台字形，换成宋体+黑体后更贴近
  中文学术报告惯例。
- **结构**：与英文版一一对应——摘要、1 引言、2 数据集、3 问题形式化（3.1–3.5）、
  4 模型（4.1–4.3）、5 实验（5.1–5.6）、6 讨论与局限、7 结论、声明、参考文献、
  附录 A 可复现性。5 张表 + 4 张图（图 2 在中文版里把英文版并排的 fig11/fig12 合成
  一张双联图，减少浮动体；其余编号 1–4 与英文版一一对应）。

## 遇到的问题与解法

1. **中文字体缺失风险（先查后做）**：先 `fc-list :lang=zh` 确认 WSL 只有文泉驿正黑
   与 AR PL 系列（港台字形），再决定从 `/mnt/c/Windows/Fonts` 复制宋体/黑体/雅黑到
   `~/.local/share/fonts/`（用户空间，无需 sudo），`fc-cache -f` 后确认
   `SimSun/SimHei/Microsoft YaHei` 三者可见。
2. **Write 工具写不进大文件（沿用 R5 已记录的坑）**：`report_zh.html` 约 38 KB，
   单次 Write 必然失败，改为 bash heredoc（引号定界 `'HTMLEOF'`）分 3 段追加。
3. **HTML 标签闭合自查**：写完用 Python `html.parser` 跑一遍栈式检查，确认
   `unclosed: []`，避免手写标签错位导致 Chrome 静默丢内容。
4. **视觉模型低分辨率幻觉（失败尝试，已纠正）**：用 gs 转 65 DPI PNG 交给视觉模型
   查版式，模型报告"存在 `\r`/`^T`/`\d` 控制符乱码"并凭空提到 IPCC/HadEX3/cvar/
   "4.3.1 编码/4.3.2 解码"等本文不存在的内容。改用 `gs -sDEVICE=txtwrite` 直接抽
   PDF 文本层核对：控制字符 0、U+FFFD 0、表图数字全在——**是 65 DPI 下的误读，不是
   真乱码**。教训：CJK 排版校验要查 PDF 文本层，不要信低分辨率视觉模型的"乱码"报告。
5. **HTML 单文件体积**：`report_zh.pdf` 2.1 MB（内嵌 4 张 PNG 图 + 字体子集），
   英文版 660 KB（LaTeX 引用同一批 PNG）。体积差源于 Chrome 字体嵌入方式，不影响
   使用；如需瘦身可把图转灰度或改用 JPEG。
